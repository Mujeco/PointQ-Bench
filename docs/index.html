03 / THE DIAGNOSTIC STANDARD

Fluent is not
faithful.

A convincing report is not necessarily a correct one. SSFRQ-5D separates coverage, specificity, grounding, reasoning, and the final quality decision.

012

Five dimensions. Three ordinal scores.
Sum reported out of 10.

Read the evaluation protocol ↗
S1

Structural Sufficiency

Does the report include an overview, defects, and a final judgment?

S2

Specificity

Does it describe concrete geometric or attribute evidence, rather than generic claims?

F

Faithfulness

Does it agree with the reference evidence without inventing defects?

R

Reasoning Coherence

Do the cited defects logically support the usability conclusion?

Q

Quality Accuracy

How close is the final decision to the reference usability level?

Ambiguity is part of the benchmark.

High-consensus samples form Official-Clean. Valid but ambiguous samples remain in Boundary-Valid, so disagreement is studied rather than silently removed.

How to merge the point cloud parts +

Download all four .zip.001 to .zip.004 parts, the parts checksum file, and merge_pointcloud_parts.py into the same directory. Run: 

python merge_pointcloud_parts.py

The script verifies each part and the reconstructed archive before completing. Unzip PointQ-Bench_pointclouds_v1.0.zip afterwards. The files in the share include full instructions and both checksum lists.
